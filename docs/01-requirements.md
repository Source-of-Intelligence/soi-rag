# RAG工具需求规格说明书

## 1. 项目概述

### 1.1 项目背景
构建一个功能完善的检索增强生成(RAG)工具，支持多种检索方式，为LLM提供高质量的上下文信息。

### 1.2 目标
- 提供多种检索能力（向量检索、关键词检索、知识图谱、PageIndex）
- 支持混合检索和智能重排序
- 提供易用的API和CLI接口
- 高性能、可扩展的架构设计

## 2. 功能需求

### 2.1 核心功能模块

| 模块 | 功能描述 | 优先级 |
|------|----------|--------|
| PageIndex | 文档页面级别的索引和检索 | P0 |
| 知识图谱 | 实体关系图谱构建与推理检索 | P0 |
| 向量检索 | 语义相似度检索 | P0 |
| 关键词检索 | BM25/TF-IDF等传统检索 | P0 |
| 混合检索 | 多路召回融合 | P1 |
| 重排序 | 精排优化 | P1 |

### 2.2 详细功能需求

#### 2.2.1 PageIndex模块
- 支持多种文档格式（PDF、Word、Markdown、HTML、TXT）
- 文档分块策略（固定长度、语义分块、递归分块）
- 页面元数据提取（标题、作者、时间、URL等）
- 增量索引更新
- 文档版本管理

#### 2.2.2 知识图谱模块
- 实体识别与抽取
- 关系抽取与构建
- 图谱存储与查询
- 基于图谱的推理检索
- 可视化支持

#### 2.2.3 向量检索模块
- 支持多种嵌入模型（OpenAI、本地模型、多语言模型）
- 向量数据库集成（Milvus、Pinecone、Qdrant、Chroma）
- 近似最近邻搜索（ANN）
- 向量量化与压缩
- 多向量表示（ColBERT、late interaction）

#### 2.2.4 关键词检索模块
- 倒排索引构建
- BM25评分算法
- TF-IDF向量化
- 布尔查询支持
- 模糊匹配与拼写纠错
- 同义词扩展

#### 2.2.5 混合检索模块
- 多路召回（向量+关键词+图谱）
- 结果融合策略（RRF、加权融合）
- 查询路由

#### 2.2.6 重排序模块
- 交叉编码器重排序
- 基于LLM的重排序
- 多阶段检索优化

## 3. 非功能需求

### 3.1 性能要求
- 索引构建：支持100万文档/小时
- 查询延迟：P99 < 200ms
- 并发支持：1000 QPS

### 3.2 可扩展性
- 水平扩展支持
- 插件化架构
- 配置驱动

### 3.3 可靠性
- 数据持久化
- 故障恢复
- 监控与告警

## 4. 技术选型

### 4.1 编程语言
- Go（核心引擎，高性能）
- Python（模型推理，NLP处理）

### 4.2 存储系统
- PostgreSQL（元数据、结构化数据）
- Redis（缓存、消息队列）
- Elasticsearch（关键词检索）
- Milvus/Chroma（向量存储）
- Neo4j（知识图谱）

### 4.3 嵌入模型
- OpenAI text-embedding-3系列
- BGE-M3（多语言）
- E5系列
- GTE系列

### 4.4 部署
- Docker容器化
- Kubernetes编排
- REST API + gRPC

### 技术栈调整

| 原设计 | 实际实现 | 说明 |
|--------|---------|------|
| Redis 缓存 | LRU 内存缓存 (pkg/cache) | 轻量级替代，满足单机场景 |
| Elasticsearch 关键词 | SQLite FTS5 / PostgreSQL tsvector | 减少外部依赖 |
| Milvus 向量存储 | SQLite BLOB / PostgreSQL pgvector | 轻量级替代 |
| Neo4j 图谱 | SQLite / PostgreSQL 关系表 | 减少外部依赖 |
| Python 模型推理 | OpenAI API / Ollama API | 无需本地 Python 环境 |
